# Independent audit and stop decision

The frozen study cannot proceed faithfully with the sealed selections. No input, existing code, log or branch artifact was modified by this audit. The frozen protocol requires score maximization subject to random row and column totals, then only degree-preserving exchanges that retain or increase that score. `match.py:19-36` instead enforces random counts within each magnitude stratum during optimization. An independent linear program using the original candidate pool, sealed random row/column totals, and scores demonstrates the violation for seed7_A `blocks.0.moe.experts.0.fc1.weight`: sealed high score 1406.4116603967439, optimum 3021.7961539078615. The optimum solution was integral (maximum fractionality 0). Reproduce from this directory using `OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python3 audit_selection_optimum.py`. This comparison does not claim the optimum passes the balance gates; the frozen protocol requires both the optimization procedure and acceptance checks. The existing metadata's `passed` checks do not check the required optimum. Regenerating the selection is explicitly prohibited, so the pilot is stopped, not repaired by changing the registered experiment.

## Inventory and integrity

The protocol and registration, prefixes (step-250 checkpoint, verification, scores, next-step oracle), and matching selections and audits are existing frozen experimental inputs. `prefix.py`, `match.py`, and `study_common.py` generated or load those inputs. `branch.py`, `branch_v2.py`, `launcher.py`, `launcher_v2.py`, `results_checker.py`, execution reports, and `branches/` are later execution code or artifacts, not trusted completion evidence. The repository has many unrelated pre-existing tracked modifications and untracked research files; `git status --short` showed modifications to pyproject.toml, the fixed-budget runner, recovery runner, model files, and test_model.py. Do not treat these as changes made by this audit. The study results directory is ignored by Git.

SHA-256 of protocol.md matched registration. All six selection, matrix audit, prefix checkpoint, and score hashes matched their corresponding metadata. Existing prefix verification records report model, optimizer, and scaler equality on restoring step 251 for all six cells; this audit did not independently rerun those GPU checks. Hash matching establishes integrity against metadata, not scientific correctness. The prior verification report's matrix count table mistakenly multiplies the cell deletion total by 256.

## Confirmed continuation defects in branch_v2.py

- Lines 19-20 index selections with public arm names, whereas match.py stores keys `random` and `high`; pruned arms fail before training.
- Lines 68 and 94 load only the prefix model into a recovery API that initializes a fresh AdamW and scaler (`run_router_age_recovery.py:460-477`); saved prefix optimizer, scaler and RNG are not restored. The continuation therefore changes the optimization trajectory.
- Lines 28-29 supply the initial router checkpoint. The recovery API assembles the model with that router, so the trained step-250 router is replaced before training.
- Lines 34-37 use local steps 1–2250, corresponding to global 251–2500. Lines 81-88 instead treat local 251 as global 251 and wait for local 2500, which cannot occur. The callback crashes on its undefined `timestamp` key at local 251 (global 501). The pilot log confirms the crash. The endpoint checkpoint, if reached, would be written at local 2250 because the native API explicitly saves at the final step; line 98 incorrectly expects 2500.
- Lines 74-79 release the branch lock before training, allowing conflicting processes. Line 71 accepts a completion JSON without verifying artifacts. The native output directory from a failed attempt can also prevent safe retry.
- Lines 43-57 replace the registered 24 GiB/90% utilization GPU admission policy with a 70% free-memory rule. No GPU branch was launched by this audit.
- The native recovery path was built for a fresh optimizer and its masks do not establish the protocol's gradient masking and optimizer-moment clearing. The runner does not implement the registered immediate before/after deletion and global 251/275/500/1000/2500 validation schedule. The existing pilot output is not a valid study outcome.

The original prefix checkpoint records step as optimizer attempts; verification records 249 applied updates and one AMP overflow among the first 250 attempts. Any continuation must separately record attempted and applied updates. The intended mapping is prefix attempt 250 = local 0; local 1 = global 251; local 2250 = global 2500. The claimed branch result at local 251 is neither immediate post-deletion nor global 251.

## Status and remaining work

At audit time no matching branch or launcher process was observed. There is one failed attempt, seed7_A untouched, evidenced by pilot_debug.log and partial native logs; 17 branches have not started. No branch has a validated final checkpoint. The existing checker is not reliable. A live-process-aware replacement, corrected runner, launcher, independent full selection audit, GPU smoke tests and three-arm pilot were not completed. No claim is made that all checkpoint schemas, RNG semantics, masks, or matching gates were independently verified. The GPU was observed at 93% utilization, above the registered limit at that instant.

The primary registered metric is validation cross-entropy at global 2500, high minus random, aggregated as A/B means within each seed and then an unweighted mean across three seeds. Immediate pre/post deletion and later measurements are separately required. Resolving the sealed-selection conflict requires a scientific decision and an explicitly authorized protocol disposition; neither silent reselection nor relabeling the existing selection as compliant is justified.
