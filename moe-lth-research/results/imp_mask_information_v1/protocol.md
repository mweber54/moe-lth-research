# IMP mask information v1: prespecified protocol

Primary endpoint: final validation CE in nats/token at 2,500 attempted recovery updates. Primary contrast: mean matrix-matched random CE minus IMP CE. Positive favors IMP; negative favors random. No direction is assumed.

## Audit and eligibility

`checkpoint_inventory.csv` enumerates committed nonzero-sparsity IMP recovery stages, their exact masks, original initialization, architecture, protocol, dense comparator, and verified file identities. `audit_details.json` includes validation of every stored IMP mask, including those awaiting recovery. `secondary_catalog.csv` inventories the broader non-IMP ticket and lower-sparsity/router-age controls; these source-final one-shot masks must never be substituted for IMP. `extended_recovery_inventory.csv` records the distinct 5,000-step endpoints. E12 and E24 are planned in the original configuration, but have no committed IMP masks/recoveries in the current tables; exclude pending artifacts rather than regenerate discovery.

IMP uses expert-local magnitude selection across fc1/fc2 weight matrices, integer rounding, stable ties, and a nested discovery trajectory. Biases, routers, attention, embeddings, norms and output weights remain dense. Masks are independently stored bool dictionaries keyed by exact parameter name; checkpoint extraction is unnecessary. Lower IMP discovery stages are eligible secondary configurations only where an actual recovery of that same mask exists (the stage that produced a mask is not its recovery).

Repository 2/5/10 percent CE screens are descriptive. Report sparse-better-than-dense, exact dense endpoint match, near-dense within 5%, and above-5% separately. No formal winning-ticket/equivalence claim follows from these screens; untouched held-out evaluation and independent seed uncertainty remain absent. Only matched budget/data/initialization comparisons can receive a descriptive status.

## Recovery matching

Use the existing canonical `scripts/imp_80_85/run.py::run_stage` and `_run_recovery_condition` trainer. Every condition loads the entire exact stored step-0 model, including router and shared parameters. Native router, shared parameters, and surviving experts remain trainable. Fresh AdamW (LR 0.0003, weight decay 0.01, default betas/epsilon), fresh GradScaler, no LR scheduler, FP16 on canonical torch 2.7.0; clip norm 1.0. Batch 128, length 128, byte-tokenized balanced multidomain data, auxiliary weight 0.1, fixed seeded batch order. Reconstruct all 2,500 batches and 32 validation batches and require exact recorded sequence hashes. Architecture comes from the rewind checkpoint, never an inferred replacement. Log attempted and applied updates, since AMP skips can differ by mask.

Masks zero gradients and are reapplied after every attempted update, preventing momentum or decay from causing effective regrowth. Initial, 50-step and final validation diagnostics, per-attempt train CE and auxiliary loss, gradients, expert utilization and routing agreement use the existing trainer. Record wall time and GPU model; elapsed GPU hours are an occupancy proxy, not billed cost. Save complete masks, seeds, config and logs. Safe weights-only checkpoint deserialization is required; no unrestricted pickle loading.

The 5,000-step extension is a different two-phase protocol: original 2,500-step weights followed by a fresh AdamW/scaler restart and the next 2,500 data batches. A random-mask extension would need its own first phase and matched restart, including dense controls. Do not mix these with primary endpoints.

## Controls and pilot

A: stored IMP. B: global fixed survivor count across exactly eligible weights. C: fixed survivor count per layer/expert across matrices. D: fixed survivor count per matrix. Draw uniform subsets with deterministic CPU generators, rejecting complete equality with IMP unless all feasible masks are identical. Validate names, bool dtype, shapes, total/expert/matrix budgets and protected parameter scope. Save all generated masks and their hashes. Five independent seeds per B/C/D, with the training seed/batch order fixed at the checkpoint seed. These are nested mask realizations, not independent training-seed replicates.

Select one verified 80% high-sparsity configuration, prioritizing a sparse-better-than-dense descriptive endpoint. Rerun A first with the full original budget; halt before B/C/D if absolute final CE discrepancy exceeds 0.005 nats/token, any identity/data/integrity check fails, or the canonical environment is unavailable. This 0.005 reproducibility tolerance is distinct from the equivalence margin. Reuse the source A only after successful validation. One A plus 15 null recoveries is the initial bounded pilot. Other architectures/seeds and eligible nonwinning configurations remain in the inventory for review after the pilot; no automatic expansion or discovery regeneration.

Before launch, save a compute estimate using actual completed recovery durations for the selected architecture (median and range), and separately the original 20-step E8 benchmark as a conservative provisional scenario. Sixteen full-budget recoveries are necessary even for this one-checkpoint pilot. Shared GPU contention makes estimates uncertain.

## Analysis and expansion

Practical equivalence margin fixed before inspecting random-mask results: +/-0.02 nats/token for the matrix contrast. Report all individual random-mask endpoints, mean, sample SD, range, and the rank/percentile of IMP in the null distribution. No seed-level inference from one pilot checkpoint. With expanded independent training seeds, aggregate mask replicates within checkpoint first, then paired seed-level effects within architecture/sparsity/router protocol; resample training-seed clusters (retaining all repeated sparsities from each seed). Report per-architecture/per-sparsity effects and seed-cluster intervals only with adequate independent clusters. Do not pool nested masks as independent observations. Equivalence requires a prespecified TOST or a 90% cluster interval entirely inside the margin, not a nonsignificant difference. Sparse-better, near-dense and nonrecovering moderators are descriptive until replicated.

Produce final CE comparisons, random distributions, representative curves, advantage versus sparsity and architecture when actual pilot results exist. Do not plot planned cells as observations. Label one-checkpoint sparsity/architecture figures as descriptive single points. If matrix controls are meaningfully worse (pilot mean gap above 0.02 and consistent direction across its five masks), review expansion first. Only after replicated support implement degree-preserving row/column swaps with mixing diagnostics. Residual advantage is not evidence of individually indispensable edges, routed-token information, or disrupted early learning. Stop and debug a failed IMP reproduction before interpreting null masks.
