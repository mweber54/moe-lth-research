# Coverage and cohort selection

Retrospective exploratory audit completed before weight/exposure associations. All five existing 32E source seeds (7,17,29,43,61) are eligible; no performance selection. Original source training is native, unpruned, 2500 attempted FP16 AdamW steps. Source has no interior optimizer reset. Step0 is initialization only. Primary checkpoints use the common grid 0,250,500,1000,1750,2500 to bound CPU sorting. Extra 125-step checkpoints for the first three seeds are inventoried but excluded by coverage rule.

Recovery, sparse recovery, reset continuations, and IMP discovery rounds are distinct families, inventoried from existing manifests and excluded before associations. Round00 is still discovery/recovery protocol, not original source. No checkpoint or log from these families is joined to source. Unselected families have path/step inventory but their large checkpoint files are not rehashed; missing hashes are explicit rather than invented. Selected original source checkpoints are byte-rehashed; bit-identical file duplicates are removed, and model-state duplicates against dense reset initializations are audited separately. Expert identities are never aligned across source seeds.

Full per-attempt source exposure logs provide exact proposed and accepted counts and applied-update flags. Dropped=proposed-accepted. Cumulative counts use all steps, not sampled usage diagnostics. Gate-weighted exposure, historical accepted-token composition, hidden-input statistics, and domain labels are unavailable. Context snippets are deterministic first-two proposed assignments, lack acceptance, and cannot estimate accepted composition. Fixed validation assignments describe proposed membership on a fixed probe, not historical training-token inputs or accepted dispatch. Native routing changes can include shared-network development.

Rank sorting pools fc1 and fc2 under the repository expert-local budget; biases/shared weights are excluded. Coordinate identity is exact parameter name and row-major index. Deterministic ordinal tie handling is distinguished from unspecified torch.topk boundary ties. Final IMP masks are not used as usefulness labels. Hypothetical disagreements do not demonstrate pruning damage, and magnitude does not establish functional importance.
