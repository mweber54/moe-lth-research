# Bounded IMP adaptation factorial v1

Registered before new recovery outcomes. Question: does restricting router or shared adaptation disproportionately impair IMP recovery relative to the same unpruned MoE? This is a dependence-on-training-process experiment, not an assumption that router adaptation explains sparse outperformance.

## Fixed cohort and estimands

E32, seeds 7/17/29/43/61; each seed has dense/unpruned, own original IMP .80, own original IMP .85. Retain all ten sparse variants regardless of historical match. Four conditions per variant: full(E,R,S), expert_only(E), expert_router(E,R), expert_shared(E,S). E includes all expert weights AND unpruned biases. R includes router parameters. S includes every other unique parameter, including tied embedding/output counted once. Audit names, identities, exhaustive disjoint grouping and tying. Sixty slots; dense reused across both sparsity comparisons. No other architectures/sparsities, discovery, random masks, expert-frozen conditions, router/gate swaps or followups.

Primary: original full-validation mean-token CE at 5000 attempted updates, native CUDA FP16 evaluation over the original 32 batches. Do not replace it with corrected-audit FP32 diagnostic CE or geometry probes. At every 50-step evaluation (including 0/2500/5000), G_c=CE_sparse,c-CE_dense,c; D_c=G_c-G_full. Router contrasts G_expert_only-G_expert_router and G_expert_shared-G_full. Shared contrasts G_expert_only-G_expert_shared and G_expert_router-G_full. Interaction I=G_full-G_expert_router-G_expert_shared+G_expert_only. Record sparse loss change and dense loss change separately so D_c=delta_sparse-delta_dense. Report absolute losses, strict same-condition CE match and recovery relative to original full dense endpoint. A favorable gap from dense deterioration is not recovery of the original level.

Equal seed weights, n=5, separate .80/.85 summaries, descriptive SD/range/t intervals and sign consistency. Shared seeds/dense references make two sparsities dependent. No favorable seed/condition/timepoint selection, no equivalence from nonsignificance. Historical match labels are annotations only.

## Exact native protocol

Every condition starts from its own verified complete original step-0 state and R0 router; sparse masks touch only original eligible expert matrices. All four conditions of a variant have identical initial tensors, native forward and validation CE. Native AdamW defaults beta(.9,.999), eps1e-8, LR.0003, WD.01, clipping1, no scheduler; batch128 x length128, byte balanced-multidomain data, capacity1.25, top1, auxiliary weight.1, torch2.7.0 CUDA FP16. Use deterministic materialized 5000-batch stream: first 2500 then second 2500. Call the unchanged native recovery function twice. Boundary preserves every model tensor and recreates model assembly/seed_everything(seed), AdamW and scaler exactly like imp_extended_recovery/pipeline.py. This is fresh-optimizer continuation, not continuous optimizer state. Record boundary model identity, optimizer entries=0 and scaler state, both batch hashes, applied updates and AMP skips.

A local adapter applies requires_grad before the native optimizer is built; the native requires_grad filter excludes frozen parameters from AdamW/decay. No no_grad/detach around frozen modules; keep normal train/eval behavior and native auxiliary objective. Original forward/backward/update code is unchanged. Persistent masks/hook zeroing remain active. Frozen tensors are compared bit-for-bit after EVERY attempted update, using device-resident reference copies; masks are checked at snapshots and end. Canonical clipping is unchanged, restricted to actual optimizer parameters. New runs log its returned native norm and coefficient at every attempt, with AMP/nonfinite flags. Historical full coefficients, when direct return values are unavailable, are explicitly reconstructed from logged preclip norms and labelled as such (not exact FP32 coefficient evidence). This is a reuse diagnostic limitation, not an excuse to claim a purely routing effect.

## Lightweight diagnostic definitions

Fixed checkpoints 0,100,2500,2600,5000, plus 2500-after-reset integrity record. Same validation batch 0, in complete 128x128 structure, is the fixed routing/gradient probe; save token/target hash. Native routing is recomputed. Save proposed and accepted counts, dropped-assignment fraction per layer, selected confidence, full-softmax entropy and top1 assignment vectors. Compare each run against its own initialization and corresponding same-seed/variant full snapshot at the SAME step. Frozen R does not imply frozen decisions/exposure, since earlier experts can alter later router inputs.

Update metric common to new and reused conditions: actual net parameter displacement between successive FIXED diagnostic checkpoints, by E/R/S, plus cumulative displacement from initialization. Label intervals explicitly; net displacement is not sum of per-step path lengths. Normalize by the corresponding preceding parameter L2 norm; zero denominator is undefined (null). This permits exact reuse of full model snapshots, including S; no missing one-step S update is fabricated. Save frozen-group zero-drift checks separately.

Task/auxiliary gradients are separate autograd.grad evaluations on the fixed diagnostic batch and current native model state, with actual trainability flags and native auxiliary weight. Use FP32, no scaler or optimizer step, canonical TF32 flags; this is a diagnostic precision, not production CE. Record named-tensor norms, group total L2, eligible coordinate counts, RMS L2/sqrt(N) and L2/N, and defined nonzero-denominator ratios. Sparse expert weight denominators include ONLY surviving coordinates; expert biases remain fully counted. Frozen groups are labelled nontrainable with no requested gradients; upstream gradients still flow. Autograd.grad does not overwrite .grad; protection verifies RNG/modes/gradients unchanged. Proposed/accepted counts are route assignments on the complete probe, not guaranteed fixed exposure in training. Diagnostics do not run SVD or embedding geometry.

Save only five diagnostic model snapshots per new run, segment-end final model files and two retained resumable segment-end states. A rolling interruption state every100 attempts preserves model/optimizer/scaler/all RNG families, consumed materialized-batch position and log sizes; truncation/resume follows canonical behavior. Record storage and throughput estimate before launch. Keep diagnostic memory bounded; snapshot comparisons use named unique parameters and CPU reference tensors.

## Execution and limits

One detached worker per Viper/Adder, GPU memory admission at least max(24GiB,1.25*measured validation peak), shared exclusive claims, per-host locks, atomic statuses and 15-second heartbeats. Fresh attempt directories, no automatic retries or overwrites, no unrelated process termination. Technical/integrity failures stop dispatch; validation loss never triggers early stopping. Run all registered slots after validation; do not extend unsuccessful conditions.

Freezing S freezes initially untrained attention and tied embedding/output. Failure describes this restricted protocol, not universal recoverability. Global clipping and optimizer dynamics change with the trainable set. Fixed-budget deterioration may be slower learning. A differential sparse/dense effect is a candidate dependency, not a uniquely identified mechanism, proof of compensation/novelty or routed-token explanation. Similar deterioration supplies little explanation of sparse advantage. Geometry audit corrections are not causal evidence and no full geometry rerun is authorized.

Final report must distinguish reused/new, running/completed/failed, primary native CE from diagnostics, sparse deterioration from dense deterioration, and unresolved explanations. Save every seed effect and curve before aggregates; no statistical independence is assigned to shared sparsity comparisons.
