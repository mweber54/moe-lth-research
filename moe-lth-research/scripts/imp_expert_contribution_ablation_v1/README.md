# Checkpoint-only expert contribution ablation

Run `OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=4 .venv/bin/python scripts/imp_expert_contribution_ablation_v1/run.py --evaluate` from the repository root. `--audit-only` verifies sources and freezes configuration without GPU evaluation. No training entry point is called. Only verified step-1000 parent snapshots and step-1500 shared-only snapshots are loaded; sparse starts apply the already registered mask to a temporary in-memory copy.

The canonical source audit is reused from `scripts/imp_capacity_diagnostic_v1/run.py` with its output directory redirected exclusively to this study. It checks source masks, registrations, common parents, numerical settings, full validation identity, shared movement and frozen router/expert weights and biases. Historical aliases count once. `results/imp_postpruning_adaptation_v1/cohort_status.json` covers the four production seeds; seed 17 is the separately completed engineering pilot. The audit validates all five individual branch status records, rather than relying on that production-only summary.

Read sources: compensation audit/configuration and completed analysis status; capacity README/configuration/completion, implementation and tests; post-pruning registration/protocol and engine/common/worker partition; IMP-transition manifest/input/supplemental manifests and source checkpoint inventory; original token-expert slot replay, evaluation_amendment_v1.md, evaluation_repair.py, corrected interpretation and replay tests. The repair establishes checkpoint-local validation capture, not training-schedule replay. The new isolated `replay.py` copies the complete accepted-slot dispatch and preserves native accepted evaluation order. Its signature accepts the new model's capacity/chunking keywords on the native path; replay explicitly rejects nonnative capacity or chunking. No prior sealed implementation is edited.

The contribution hook zeros exactly the MoE module's first returned value before the block adds its attention residual. Full selected gate weighting, capacity acceptance and both expert biases are included. Replay runs frozen experts on current hidden inputs. Internal native router probabilities in replay are excluded from imposed-route summaries. No expert chunking is used.

Tests run before admission. An independent full native readout must reproduce the registered baseline before the first ablation profile. The full one-batch 12-cell profile gates dispatch and records its bounded 20-checkpoint projection. Each full checkpoint cache is atomic and requires all interventions/modes/batches, source seal, checkpoint, mask, validation sequence and per-batch identity. Interrupted partial checkpoints are recomputed. Failed attempts are retained. All logical baseline and ZERO_ALL cells are evaluated explicitly rather than reused.

Admission and locking reuse the existing shared-only worker helpers (90% maximum utilization, 24 GiB free GPU, 200 GiB free storage). Use the established Viper/Adder SSH transport to select an admitted host; do not run duplicate workers or interrupt unrelated jobs. Summary results are written only from 20 complete validated checkpoint caches. Five source seeds are the replication units.

`verify_shared.py` performs the supplemental direct start/end comparison for all ten pairs and saves `shared_parameter_verification.json`, including separate shared/router/expert group hashes, bias counts, changed tensor names and L2 movement. Run it before evaluation when using this workflow independently. The supplemental check and reporting code are separately sealed in `reporting_seal.json` before new outcomes. The original `source_configuration_seal.json` covers the evaluator, replay, model code, configuration and canonical provenance file.

After the main evaluation completes, run `.venv/bin/python scripts/imp_expert_contribution_ablation_v1/review.py` to independently validate all 240 logical cells and 7440 batch records, check arithmetic identities, render the five requested figures, append explicit A–H interpretation and refresh `summary.tar.gz`. Reports retain individual seed values before descriptive cohort summaries. `compute_accounting.json` separates cohort, pre-cohort native gate and profile forwards.

Supplemental norm convention: `shared_parameter_verification.json` reports `delta_l2` over state-dict entries, so the tied embedding/head alias appears twice in that descriptive norm. Exact group equality and the assertion that shared tensors changed do not depend on this duplication. It is not a component attribution or a count of independent parameters.
