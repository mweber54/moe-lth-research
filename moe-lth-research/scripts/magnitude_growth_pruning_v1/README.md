# Controlled magnitude-growth pruning intervention

This experiment has fifteen registered production branches: five original unpruned 32E source seeds × newly run control / growing-small removal / magnitude-matched stable-small removal. It branches at source1000 with past-only250/500/1000 histories and a common fresh optimizer/scaler/RNG reset, then consumes the exact original source batches1001–2500. It is separate from IMP and historical sparse recoveries.

`prepare.py` requires a new output directory, audits checkpoint/state coverage, registers definitions, matches all five seeds, saves compact coordinate masks/hashes, and verifies the source data stream before any loss calls. `validate.py` performs synthetic and short canonical gradient/resume/state-preservation tests. `cluster.py` seals code/protocol/registration and detaches one established Viper/Adder worker each. `worker.py` releases the other seeds only after numerical/resource success of all seed17 branches. Registered outcomes never enter dispatch decisions. Existing attempts and failures are preserved; no automatic retries or scope expansion are allowed.

`run.py` writes initial-integrity records, per-attempt training logs, fixed-step task-CE curves, per-batch validation counts, full serialized interruption state, and a final step2500 model with hashes. Continuation uses FP16/autoscaling; validation uses FP32 with TF32 disabled and original complete batches. All parameters remain trainable except that selected expert-weight coordinates receive zero gradients and are zeroed after every attempted update. The full interruption state includes optimizer moments, scaler and all RNG states.

Explicit resume uses the same attempt and its execution lock, for example `run.py --seed 17 --branch growing --attempt <registered-attempt-path> --resume`. Stop the owning experiment worker safely before taking over an attempt. Identity checks reject altered masks, data, registration or code. Resume restores committed metrics and truncates only the uncommitted tail of that attempt's own log. Do not create a new branch to retry a favorable or unfavorable result.

`report.py` retains all registered branches, including pending/failed ones, and renders the complete five-seed report only when every seed has all three results. `balance_figures.py` adds exact magnitude-distribution and matrix-specific history plots using only source1000 and sealed matching summaries. `final_audit.py --review-file <review.md>` verifies every production checkpoint, mask zero, update count, source offset and validation token count, then appends a reviewed scientific conclusion without changing sealed production code.

All outputs are isolated under `results/magnitude_growth_pruning_v1/`. No historical artifact is written. Matching counts/magnitude does not match structural connectivity. The intervention tests the candidate selection rule, not a routing mechanism or a full pruning schedule.
